# BP6 MCP server, phase 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A separate `buspirate mcp-bp6` MCP server for the Bus Pirate 6, with recipes that turn "get this LCD / sensor / flash chip / GPS working" into one plan and one yes, for everything the BPIO2 binary interface can do.

**Architecture:** A new package `buspirate/mcp_bp6/` sits on the stage 1 core in `buspirate/mcp/` (session, power, confirm, wiring, jobs), which is reused, not copied. Recipes are data (one `Recipe` per use case, grouped by bus) run by one engine: `plan_recipe` measures, builds the wiring and power plan and issues a token; `run_recipe` redeems it, applies power, checks the target and does the job. New chip drivers go in `buspirate/devices/` so the universal server and the app gain them too.

**Tech Stack:** Python (core 3.8-clean), `mcp` SDK ≥2.3 (server module only, Python ≥3.10), `anyio`, pytest, the BPIO2 flatbuffers already vendored in `buspirate/bp6/bpio/`, the `FakeBp6` simulator.

**Spec:** `docs/superpowers/specs/2026-11-10-bp6-mcp-server-design.md` (phase 1 = section 6 item 1). Research: `docs/superpowers/research/2026-11-10-bp6-use-cases.md` (per-device addresses, commands, datasheet facts — read the entry for each recipe you build).

## Global Constraints

- Everything outside `buspirate/mcp_bp6/server.py` stays Python 3.8-clean (no `match`, no `X | Y` types, no `mcp`/`anyio` imports). Run the 3.8 check in the final task.
- Tests: `.venv/bin/python -m pytest tests/ -q` (3.9, no MCP SDK; server tests skip) and `uv run -q --isolated --python 3.13 --with-editable '.[dev,mcp]' python -m pytest tests/ -q`. Never a plain `uv run` (it rebuilds `.venv`).
- The universal `buspirate` server's behaviour and tool list do not change, except for gaining the new chip drivers through the shared catalogue. Its tests keep passing unchanged.
- Power is never switched on without a redeemed confirmation token. Tokens: single use, 300 s (existing `ConfirmStore`).
- Confirmation rule: a recipe plan at the recipe's default voltage needs one yes, even above 3600 mV. `needs_extra_confirmation` is true only when the owner's voltage override is above the recipe's default, or the current limit is 0.
- No recipe in phase 1 erases or writes memory. The `destructive` risk level exists in the data model, and the engine refuses to run it ("arrives in phase 2").
- On server exit the board goes to HiZ (supply and pull-ups off): `session.disconnect()` already does this through `close()`.
- The server connects on first use, never at start-up.
- Wire colours and pin names come from `buspirate/mcp/wiring.py`/`boards/bp6.py`, never typed into recipes as free text.
- Commit after every task with a `bp6-mcp:` prefix, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Branch: `bp6-mcp`, cut from `main` after PR #45 is merged (or from `i2c-write` if it isn't yet). Cherry-pick commit fe774e6 (the design and research docs) onto it.

## Review Focus

1. **A target that already has its own power.** A UART console or GPS on a powered board: `recipe_plan` must see the voltage and plan *target-powered* (supply off), never plan to switch the supply on into it. Test in Task 6.
2. **A measured voltage outside the recipe's range** (a 5 V board for the SHT4x, at most 3600 mV): refuse with the reason, issue no token. Test in Task 6.
3. **A re-run after the owner (or `hiz`) switched power off:** `run_recipe(token=None)` must refuse, not switch power back on. Test in Task 6.
4. **A word that matches several recipes** ("eeprom", "temperature"): `find_recipes` returns all of them, ranked, so Claude asks instead of guessing. Test in Task 7.
5. **The check fails** (LCD at 0x3F, not 0x27; no flash on the bus): `run_recipe` stops before the action, leaves power on, returns what was found (scan result or JEDEC bytes) and what to check. Test in Task 8.

  - SHT3x: 0x44/0x45. Command `24 00` (high repeatability, no clock stretch), wait 16 ms, read 6 bytes, CRC-8 poly 0x31 init 0xFF. T = −45 + 175·raw/65535; RH = 100·raw/65535.

- The SHT3x and SHT4x share 0x44, so each `probe` must tell them apart (the SHT4x answers serial-number command `89`, the SHT3x answers status `F3 2D`) and return False for the other.

**Interfaces** (same `Device` pattern as Task 3):

### Task 6: The recipe model and engine

**Files:**
- Create: `buspirate/mcp_bp6/recipes/__init__.py` (model and registry), `buspirate/mcp_bp6/engine.py`
- Test: `tests/test_mcp_bp6_engine.py`

**Interfaces:**
- `Recipe`, a frozen dataclass:
  - `name: str`, `title: str`, `words: Tuple[str, ...]`, `bus: str` (a `wiring.JOBS` job, or `"led"`);
  - `default_mv: int`, `min_mv: int`, `max_mv: int`, `milliamps: int = 100`, `pullups: bool`;
  - `wiring: Tuple[Tuple[str, str], ...]` (target pin → BP6 pin name such as `"IO0"` / `"VOUT"` / `"GND"`);
  - `check: Callable[[Any, Dict], Dict]`, `action: Callable[[Any, Dict], Dict]`;
  - `options: Dict[str, Any]` (defaults);
  - `risk: str = "none"` (`"none"` | `"destructive"` | `"owner-only"`);
  - `source: str` (a docs.buspirate.com URL);
  - `notes: Tuple[str, ...] = ()`.

  `check` and `action` receive the board and the merged options, and return a dict. If `check` returns `{"ok": False, ...}`, the action is stopped.
- `REGISTRY: Dict[str, Recipe]`, `register(r: Recipe) -> Recipe`, `find_recipes(query: Optional[str]) -> List[Dict[str, str]]` (each item: name, title, bus).
- `engine.plan_recipe(session, confirm: ConfirmStore, name: str, options: Dict[str, Any]) -> Dict[str, Any]` does the following, in a `session.run`:
  1. Measure with `power.measure(bp)`; the supply is assumed off. When the BP6 supply is off, `psu_mv` is used as the VOUT reading (mark it in a comment as verified only in the simulator).
  2. If any reading is ≥ `power.SUGGEST_MIN_MV`, the plan is **target-powered**:
     - the supply stays off and `power: None`;
     - `target_mv` is the highest reading;
     - if `target_mv` is outside `min_mv`..`max_mv`, refuse with `{"error": …}` and issue no token.
  3. Otherwise build the power plan with `plan_power("bp6", mv, SOURCE_OWNER, pullups, milliamps)`, where `mv` is `options.get("millivolts", default_mv)`:
     - `mv` must be within `min_mv`..`max_mv`, else refuse;
     - `needs_extra_confirmation = mv > default_mv or milliamps == 0`, replacing `plan_power`'s own rule;
     - if `default_mv` is 0 (the "identify" recipe), you need `options["millivolts"]`, else refuse with "ask the owner for the target's voltage (3.3 V is usual)".
  4. Return `{recipe, title, wiring: [steps], power: plan dict or None, target_powered: bool, target_mv, action: str, warnings, needs_extra_confirmation, token}`. Wiring steps come from the recipe's `wiring`, with colours from `wiring.cable_colour("bp6", pin)`.

  The token payload stores the recipe name, the merged options, the plan, `session.port` and an expiry.
- `engine.run_recipe(session, confirm, token: Optional[str], options: Dict[str, Any]) -> Dict[str, Any]`:
  - **With a token:** redeem it (action `"recipe_run"`). Refuse if the port differs from `session.port`. Apply power with `power.apply_plan` (Task 1) unless the plan is target-powered; stop on a trip. Then run `check`, then `action`. Store `session.last_recipe = {name, options, mv, until: monotonic()+300}`.
  - **With `token=None`:** re-run `check` and `action` only when all of these hold: `session.last_recipe` exists; `until` hasn't passed; `session.power` is not None and `session.power.millivolts == last_recipe["mv"]` (for target-powered runs, the measured voltage is still within range); and the options only change keys outside `("millivolts", "address")`. Otherwise return `{"error": "plan again: …"}`.
  - **Risk:** `risk == "destructive"` returns `{"error": "erase and write recipes arrive in phase 2"}`.
  - **Result:** `{recipe, power, check, result}` or `{recipe, power, check, stopped: "check failed", hint}`.
  - **Session state:** add `last_recipe: Optional[Dict[str, Any]] = None` to `BoardSession`, cleared in `_drop()`.
